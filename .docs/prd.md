# PRD — Product Requirements Document

> Источник истины по продукту. Агент читает его при планировании фаз.
> Схема БД не дублируется здесь — она в `.docs/database.md`.

**Версия:** 1.0 · **Дата:** 2026-08-09 · **Статус:** утверждён к разработке

---

## 1. О продукте

**Название:** «Сдоба» — маркетплейс кондитерских изделий
_(рабочее название, меняется в `config/config.php` и в шапке макета)_

**Что это:** Интернет-магазин выпечки и кондитерских изделий с
мультивендорной моделью: несколько кондитеров-партнёров размещают свои
товары на одной витрине, покупатель собирает корзину из товаров разных
кондитеров и оформляет один заказ. Платформа удерживает комиссию с
каждого кондитера.

**Для кого:**

| Роль                    | Кто это                         | Что делает                                                           |
| ----------------------- | ------------------------------- | -------------------------------------------------------------------- |
| Гость                   | Незарегистрированный посетитель | Смотрит каталог, собирает корзину, оформляет заказ без регистрации   |
| Покупатель (`customer`) | Зарегистрированный пользователь | Всё то же + история заказов, адреса, избранное, отзывы               |
| Кондитер (`vendor`)     | Партнёр-производитель           | Свой кабинет: товары, свои заказы, статистика, выплаты               |
| Администратор (`admin`) | Владелец платформы              | Полный доступ: модерация кондитеров и отзывов, все заказы, настройки |

**Какую проблему решает:** частные кондитеры продают через соцсети —
без каталога, корзины, онлайн-оплаты и истории заказов. Платформа даёт
им витрину и приём платежей, покупателю — один заказ вместо переписки
в трёх чатах.

**Деплой:** shared-хостинг (Apache + PHP 8.2 + MySQL 8), без Node.js на
сервере, без доступа к консоли на проде.

**Назначение проекта:** портфолио. Отсюда — приоритет на реалистичность
сценариев (реальная транзакционность заказа, защита от гонок на
остатках, тестовая интеграция платёжного шлюза), а не на скорость сдачи.

## 3. Решения по макету (обязательно к прочтению перед Фазой 0)

Исходник вёрстки: **Fastkart** (Pixelstrap). Отобранный под этот PRD
срез макета лежит **внутри проекта** — в `example-template/`
(37 МБ, 722 файла: 27 страниц витрины, 30 админки, 5 писем, печатная
накладная, ассеты и 254 изображения). Карта соответствий «файл макета →
маршрут проекта → пункт PRD», список исключённого и заметки к
интеграции — в `example-template/README.md`.

Тема кондитерской — `example-template/front-end/index-2.html`.

**Правила работы с папкой:**

- `example-template/` — **read-only референс**. Файлы оттуда не
  редактируются и не подключаются напрямую
- Разметка страницы переносится в `src/Views/`, нужные ассеты — в
  `public/assets/vendor/`
- Папка **не деплоится на прод** — исключается при выгрузке на хостинг
- Все ссылки внутри проверены: 868 изображений и 1262 подключения
  CSS/JS резолвятся, любая страница открывается в браузере и работает
  вместе с интерактивом

### 3.1. Правила, которые меняются под макет

Эти пункты `CLAUDE.md` / `.claude/rules/general.md` **должны быть
переписаны** до старта Фазы 0 — иначе документация противоречит коду:

| Правило было                              | Стало                                                                                                 | Почему                                                                                                                              |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| «Не используем — никогда: jQuery»         | jQuery 3.6 разрешён как вендорная зависимость макета                                                  | Весь интерактив темы (слайдеры, зум фото, фильтр цены, анимация полёта в корзину) построен на нём; переписывание = отдельный проект |
| «Functional style only — no classes» (JS) | Действует для **своего** JS. Код макета не рефакторим                                                 | Плагины макета — сторонний код                                                                                                      |
| «Кастомные классы по BEM»                 | Классы темы (`product-box-4`, `deal-box`) остаются как есть. **BEM обязателен только для нового CSS** | Тема подключается как vendor-слой                                                                                                   |
| «Layout только Bootstrap-сетка»           | Действует. Макет и так на сетке Bootstrap 5.3                                                         | Конфликта нет                                                                                                                       |
| «Графики — Chart.js»                      | ApexCharts                                                                                            | Дашборд админки уже собран на нём                                                                                                   |

### 3.2. Слои CSS/JS

```
public/assets/vendor/    ← CSS и JS макета AS IS. Не редактируем, не форматируем
public/assets/css/       ← свой CSS поверх темы, строго BEM
public/assets/js/        ← свой JS, ES-модули, без jQuery
public/assets/img/       ← изображения макета + контент проекта
public/uploads/          ← загруженное через админку (фото товаров, логотипы кондитеров)
```

**Правило:** правка внешнего вида темы делается **переопределением** в
своём CSS, а не редактированием файлов в `vendor/`. Иначе обновить или
объяснить происхождение стиля будет невозможно.

**Цвет темы — CSS-переменная**, пересборка не нужна. Карамельный
`#d99f46` уже входит в набор Fastkart, дефолт макета — зелёный
`#0da487`:

```css
:root {
	--theme-color: #d99f46;
	--theme-color-rgb: 217, 159, 70;
}
```

**Что чинится при переносе темы в `vendor/` — задачи Фазы 0:**

- Из `@font-face` в CSS админки убираются строки с `.eot`, `.ttf` и
  `.svg`: эти форматы в `example-template/` не переносились (легаси под
  IE и Safari <10, см. §6). Иначе браузер получит 404 и нарушится
  требование «чистая консоль» из `dod-global.md`
- Google Fonts подключены в `<head>` каждой страницы макета с CDN —
  шрифты скачиваются и подключаются локально
- Демо-заглушки `example-template/back-end/assets/ajax/post.php` и
  `server-processing.php` не переносятся: данные для таблиц админки
  отдаёт наш контроллер

### 3.3. Витрина и админка — два независимых фронта

У макета два несвязанных набора ассетов: `front-end/` и `back-end/`
(свой Bootstrap, свои иконки, свой CSS). Ведём их как два слоя
представления с общим PHP-ядром: `src/Views/shop/` и `src/Views/admin/`
со своими layout-файлами. Общего CSS у них нет и не будет.

### 3.4. Локализация вёрстки

Макет англоязычный, у части страниц выставлен `dir="rtl"`. При переносе
каждой страницы: `lang="ru"`, `dir` убирается, весь текст переводится,
формат цены — `1 250 ₽`, дата — `ДД.ММ.ГГГГ`.

## 5. Функциональные требования

### 1. Каталог и товар

- [ ] **FR-CAT-01** — Дерево категорий с подкатегориями, ЧПУ-адреса по `slug`
- [ ] **FR-CAT-02** — Листинг категории с пагинацией (24 товара на страницу), без выгрузки всей таблицы
- [ ] **FR-CAT-03** — Фильтры: цена (диапазон), кондитер, наличие, вес, тег «без сахара», рейтинг
- [ ] **FR-CAT-04** — Сортировка: популярные, новые, цена ↑↓, рейтинг
- [ ] **FR-CAT-05** — Переключение вида «плитка / список», выбор сохраняется в cookie
- [ ] **FR-CAT-06** — Поиск по названию и описанию через `FULLTEXT`, не `LIKE '%...%'`
- [ ] **FR-CAT-07** — Карточка товара: галерея (до 6 фото) с зумом, цена и старая цена, остаток, кондитер со ссылкой на витрину
- [ ] **FR-CAT-08** — Карточка товара: состав, аллергены, вес/размер, срок годности, условия хранения, калорийность
- [ ] **FR-CAT-09** — Варианты товара (вес 1/2/3 кг, начинка) со своей ценой, артикулом и остатком; выбор варианта пересчитывает цену без перезагрузки
- [ ] **FR-CAT-10** — Товар «на заказ»: `lead_time_hours` — минимальный срок изготовления, ограничивает выбор даты доставки на чекауте
- [ ] **FR-CAT-11** — Быстрый просмотр товара в модалке (Quick View из макета)
- [ ] **FR-CAT-12** — Блок «Похожие товары» и «С этим покупают»
- [ ] **FR-CAT-13** — Товары не удаляются физически — `is_active = 0`

### 2. Корзина, избранное, сравнение

- [ ] **FR-CART-01** — Корзина работает у гостя (по `session_id`) и у авторизованного (по `user_id`)

## 6. Нефункциональные требования

| Категория            | Требование                                                                                                                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Производительность   | Главная и листинг каталога — до 300 мс серверного времени на 5 000 товаров. Под каждый фильтр/сортировку есть индекс в `database.md`                                                        |
| Пагинация            | Обязательна везде. Вглубь каталога — keyset-пагинация вместо `LIMIT offset, n`                                                                                                              |
| Адаптивность         | Mobile-first, корректно от 320 px. Проверяется на каждом таске по `dod-global.md`                                                                                                           |
| Доступность          | `alt` у всех изображений (включая фото товаров), семантические теги, `aria-*` в модалках и слайдерах, фокус видим                                                                           |
| Безопасность         | Всё по `.claude/rules/php.md`: prepared statements, `password_hash()`, `htmlspecialchars()` на вывод, CSRF на каждом POST, rate-limit на логин и чекаут, security-заголовки централизованно |
| Деньги               | Только `DECIMAL(10,2)`. Никаких `float`. Форматирование — только во Views                                                                                                                   |
| Логирование          | Ошибки и платёжные события — в `storage/logs/`, вне document root. Пользователю — дружелюбное сообщение без деталей шлюза                                                                   |
| SEO                  | ЧПУ, уникальные `title`/`description`, Open Graph, `sitemap.xml`, `robots.txt`, микроразметка `Product` и `BreadcrumbList`                                                                  |
| Изображения          | `loading="lazy"`, WebP с fallback, ресайз при загрузке (превью 300 px, карточка 800 px)                                                                                                     |
| Совместимость        | Chrome/Firefox/Safari/Edge — 2 последние версии. IE не поддерживается                                                                                                                       |
| Ограничения хостинга | Без Node.js на сервере, без демонов. Фоновые задачи — только через cron, и только если хостинг его даёт                                                                                     |

## 7. Схема БД

> Полная схема — в `.docs/database.md` (источник истины), зеркалится в
> `database/install.php`. Здесь только перечень того, что появляется
> сверх базового набора шаблона — без описания колонок.

**Расширяются существующие таблицы:** `users` (роль `vendor`, телефон,
аватар), `categories` (изображение, описание, активность),
`products` (кондитер, старая цена, вес, состав, аллергены, срок
годности, срок изготовления, рейтинг), `cart_items` (вариант товара),
`orders` (номер заказа, контакты гостя, доставка, промокод, расширенный
набор статусов), `order_items` (суб-заказ, вариант).

**Новые таблицы — 25:** `vendors`, `vendor_orders`, `vendor_payouts`,
`product_variants`, `product_attributes`, `delivery_zones`,
`order_status_history`, `coupons`, `coupon_usages`, `addresses`,
`wishlists`, `password_resets`, `roles`, `reviews`, `review_images`,
`banners`, `blog_categories`, `blog_posts`, `pages`, `menu_items`,
`support_tickets`, `ticket_messages`, `newsletter_subscribers`,
`cart_reminders`, `settings`.

**Ключевые архитектурные решения по данным:**

1. **`vendor_id` в `products` закладывается с Фазы 1**, хотя кабинет
   кондитера появляется только в Фазе 7. Добавлять владельца к товарам
   задним числом — это переписывание всех запросов каталога.
2. **`vendor_orders` — отдельная сущность**, не флаг в `order_items`.
   Иначе нельзя показать «торт отправлен, эклеры ещё готовятся».
3. **Снэпшоты** в `order_items` (название, цена) и в `vendor_orders`
   (процент комиссии) — история заказа не меняется задним числом.
4. **Сравнение товаров — без таблицы**, только localStorage.

## 8. Интеграции

| Сервис | Режим            | Где живёт               | Что нужно                                                                                                        |
| ------ | ---------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------- |
| ЮKassa | Тестовый магазин | `src/Services/Payment/` | `shopId` и секретный ключ в `.env`. Создание платежа, редирект, вебхук с проверкой подписи, лог в `payment_logs` |

интерфейс + класс на провайдера, чтобы второй шлюз не превратился в
растущий `match` по имени.

## 9. Вне скоупа v1.0

Явно **не делаем**, чтобы не расползался объём:

| Что                                                   | Почему                                                                                |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Мультиязычность (`translation.html`)                  | Магазин русскоязычный. Целая фаза работы ради нулевой ценности для портфолио          |
| Мультивалютность (`currency-rates.html`)              | Только ₽                                                                              |
| Цифровые товары и скачивания (`product-digital.html`) | Кондитерской не нужны                                                                 |
| Сохранённые банковские карты                          | `php.md` запрещает хранить данные карт; токенизация требует боевого договора с ЮKassa |
| Мобильное приложение, PWA, push                       | —                                                                                     |
| Realtime-уведомления, чат с кондитером                | Требуют WebSocket / Node.js, которых нет на shared-хостинге                           |
| Программа лояльности, бонусные баллы                  | Кандидат в v1.1                                                                       |
| Автоматические выплаты кондитерам                     | В v1.0 реестр выплат ведётся, перевод денег — вручную вне системы                     |
| Интеграция с 1С / складом / онлайн-кассой (54-ФЗ)     | Портфолио, не боевая эксплуатация                                                     |

Вёрстка перечисленных разделов в `example-template/` **отсутствует** —
она отсеяна при переносе. Если что-то из списка вернётся в скоуп,
файлы берутся из полного макета Fastkart (см. «Что не переносилось» в
`example-template/README.md`).

## 11. Роадмап

Фазы идут строго последовательно. Детализация каждой — в
`.docs/phases/phase-N.md`, статусы — в `.docs/phases/_status.md`.

### Фаза 0 — Фундамент

Ядро (`Router`, `Database`, `Request`, `Logger`, хелперы) уже в шаблоне.
Добавляется: схема БД и `install.php`, интеграция темы (layout витрины и
админки, вендорные ассеты, локализация шапки/подвала), авторизация с
ролями `customer / vendor / admin`, `.env`.
_Готово, когда:_ можно зарегистрироваться, войти, увидеть пустую
витрину и админку в теме Fastkart, а покупатель получает 403 на `/admin`.

### Фаза 1 — Каталог

Категории, товары, варианты, галерея, фильтры, сортировка, поиск,
пагинация, карточка товара, сид демо-данных.
_Готово, когда:_ покупатель находит товар через каталог, фильтр и поиск
и открывает его карточку.

### Фаза 2 — Корзина, избранное, сравнение

Гостевая и пользовательская корзина, слияние при входе, промокоды,
избранное, сравнение.
_Готово, когда:_ можно собрать корзину гостем, войти и не потерять её.

### Фаза 3 — Заказ и оплата

Чекаут, адреса, доставка с датой и слотом, транзакционное создание
заказа с суб-заказами, защита остатков от гонки, ЮKassa (тест), вебхук,
статусы, письма, отслеживание заказа.
_Готово, когда:_ заказ проходит путь `created → paid` через тестовый
платёж, остатки списаны корректно, письма ушли.

### Фаза 4 — Личный кабинет покупателя

Обзор, заказы, адреса, профиль, безопасность, отзывы, повтор заказа.
_Готово, когда:_ покупатель видит только свои данные и не может достать
чужие подстановкой id.

### Фаза 5 — Админка, часть 1

Дашборд с графиками, товары, категории, медиа, заказы, ручное создание
заказа, накладная.
_Готово, когда:_ магазином можно управлять без прямого доступа к БД.

### Фаза 6 — Админка, часть 2

Пользователи, роли, промокоды, модерация отзывов, доставка и налоги,
настройки, баннеры, отчёты с выгрузкой.
_Готово, когда:_ закрыты все административные сценарии из §4.4.

### Фаза 7 — Мультивендор

Заявка кондитера и её модерация, публичные витрины кондитеров, кабинет
кондитера, изоляция данных между кондитерами, комиссии, реестр выплат.

## 12. Критерии приёмки продукта

Проект считается готовым, когда все пункты проходят **ручной прогон**:

- [ ] Гость проходит путь: главная → каталог → фильтр → карточка →
      корзина → чекаут → тестовая оплата → письмо → отслеживание заказа
- [ ] Заказ с товарами двух кондитеров разделён на два суб-заказа с
      независимыми статусами и корректно посчитанными комиссиями
- [ ] Два параллельных заказа последней единицы товара: один проходит,
      второй получает внятную ошибку. Остаток не уходит в минус
- [ ] Оборванная транзакция (ошибка на списании остатка) не оставляет
      заказ-полуфабрикат в БД
- [ ] Повторный вызов вебхука ЮKassa не меняет статус и комиссию дважды
- [ ] Вебхук с неверной подписью отклонён, факт записан в `payment_logs`
- [ ] Покупатель не открывает чужой заказ, адрес и корзину по id в URL
- [ ] Кондитер не открывает чужой товар и чужой суб-заказ
- [ ] Покупатель не попадает в `/admin` и `/vendor-panel` по прямому URL
- [ ] Все страницы корректны на 320 px
- [ ] `storage/logs/app.log` чист от PHP-ошибок и warnings
- [ ] Консоль браузера чиста от ошибок
- [ ] `composer test` — зелёный
- [ ] Проект разворачивается на чистом хостинге по README за 15 минут
